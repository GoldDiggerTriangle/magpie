## 0. How to use this document (READ FIRST)

This is the handoff between sessions and between AIs (Claude ⇄ ChatGPT). The rules below exist so the project **never takes a backwards step**.

1. **Read before you act.** At the start of any session, read sections 1–6. Do not propose architecture, scope, or stack changes without checking the **Locked Decisions** (§3) first.

2. **Locked means locked.** A `LOCKED` decision is not revisited unless Regan explicitly approves reopening it. If you believe a locked decision is wrong, you may *argue to reopen it*, but you must (a) name the decision ID, (b) state it contradicts a lock, and (c) give a strong reason. You may **not** quietly build something that contradicts a lock.

3. **Decisions are append-only.** Never delete or silently rewrite a decision. To change one, add a new dated entry in the **Decision Log** (§8) that marks the old entry `SUPERSEDED` and explains why. The history must always be reconstructable.

4. **The snapshot reflects reality, not plans.** §2 “Current State” describes what is actually built and tested — never what is merely intended. Update it only when real status changes.

5. **Sign your edits.** Every edit bumps the version, updates “Last updated” + “Updated by”, and adds a one-line entry to the **Session Log** (§9).

6. **Re-upload after editing.** After a session that changes anything, save the updated file back into the Project **sources** so both AIs see the current version next time. The version number is how you tell stale from current. *(Amended 2026-11-13 by D-141: the canonical copy now lives in GitHub; see §3.)*

7. **Disagreements are recorded, not overwritten.** If Claude and ChatGPT disagree, log both positions (with author tags) under **Open Questions** (§6). Regan adjudicates; the resolution becomes a dated Decision Log entry. Never overwrite the other AI’s recorded position.

8. **Work from current artifacts only.** §2 lists every artifact with its version/status. Before implementing, confirm you’re using the latest spec, not a stale copy.

9. **Companion archive.** The full append-only history lives in `MASTER_HANDOFF_LOG.md` (complete §8 decision log + §9 session log). This working doc keeps only the most recent few entries of each plus a pointer, to stay small enough to open/download. The archive is part of the handoff — same append-only rules — but you rarely need it day-to-day; read it when you need older history.

10. **Every sprint ships with a framing note (mandatory — Regan, 2026-06-15).** Whenever a sprint is locked and its `SPRINT_N_SPEC.md` is written, **also** produce a one-page **framing/kickoff note** `SPRINT_N_KICKOFF.md` — the cover message to paste when assigning the sprint to Codex: what it is, what it builds on (current head), the few must-not-get-wrong constraints, the design direction, the reasoning level + secrets guardrail, and the closure/done gate. The detailed spec stays the contract; the kickoff note is the orientation on top. Don’t wait to be asked.

## 1. Project identity & north star

**Codename:** Magpie. **Full name:** Gold, Stamps & Phonetech.

**Product:** A serious, long-scope inventory + valuation + listing platform for a reselling/collectibles business (stamps, coins, phones/electronics, gold, tools, collectibles, bulk lots, unknown stock).

**Workflow the system serves:** `photos → inventory → research notes → valuation → listing draft → profit tracking`, with eBay publishing as a *later optional output channel*.

**North-star principle (non-negotiable):**

> The software owns the inventory truth. eBay is one sales channel, not the centre of the system. **The app must remain fully valuable even if every external API is blocked tomorrow.**

**Long-term ambition:** start as Regan’s personal business tool; keep the architecture clean enough that it could later become a product for other resellers/collectors. Do **not** build multi-tenancy/billing now — one nullable `owner` seam only.

## 10. Update protocol (full rules)

The methodical rules both AIs follow. (Summary is in §0; this is the complete version.)

1. **Single canonical copy** = this file in Project sources. Re-upload after any change. *(Amended 2026-11-13 by D-141: the canonical copy is `docs/MASTER_HANDOFF.md` on `main` in GitHub; nothing is re-uploaded.)*

2. **Versioning:** bump `Version`, set `Last updated` + `Updated by` on every edit; add a §9 line.

3. **Append-only decisions:** §3 and §8 are never destructively edited. Supersede with a dated §8 entry; update the §3 entry’s status to `SUPERSEDED` (keep the text).

4. **Decision states:** `LOCKED` (needs Regan approval to reopen), `OPEN` (in §6), `PROPOSED` (an AI’s suggestion awaiting Regan), `SUPERSEDED` (kept for history).

5. **No backwards steps:** before proposing anything that touches a `LOCKED` decision, read §3, name the decision ID, and openly justify reopening it. Silent contradiction is prohibited.

6. **Reality-only snapshot:** §2 reflects what is built/tested, not intentions.

7. **Disagreement handling:** record both AI positions in §6 with author tags; Regan adjudicates; resolution → §8. Never overwrite the other AI’s text.

8. **Artifact freshness:** check §2’s artifact index before building; never work from a stale spec.

9. **Provenance:** every edit is signed (author + date).

10. **Scope discipline:** if unsure, prefer the smaller change that satisfies the current sprint’s acceptance criteria; defer the rest and note it in §6 or §5.

*End of controlling document. Keep it current; keep it honest; never regress.*
